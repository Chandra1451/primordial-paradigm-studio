Primordial Paradigm

Work for hire

Alongside its games, Primordial Paradigm builds business dashboards: the data model underneath, the report people read, and the pipeline that keeps it current. Power BI is the main tool; a project that needs a different one can be planned around it. Work is taken on selectively, and every project is built for the client who asked for it.

What the studio builds

Data models. Star-schema models designed around the questions your reports need to answer. A documented library of DAX measures that someone else could pick up. Row-level security, so each person or team sees what they should. Incremental refresh sized to your data, and tuning so reports open quickly as the data grows.

Report design. A layout and type system that stays consistent across every page, so the report reads as one thing. Drill-throughs, bookmarks and navigation designed around how people actually use it. A contrast and legibility pass, and a reusable theme for future pages.

Data pipelines. Connections to cloud storage, source databases and third-party platforms such as CRM, e-commerce or marketing tools, brought into one model. Google Cloud and Oracle Cloud are familiar ground; other platforms can be discussed. Scheduled refresh set to how often the data really changes, and checks that catch a broken feed before it shows a wrong number.

How a project runs

  1. Discovery. Map the data sources, who reads which report, and what decisions the reports should support. Most problems are found here, before any building starts. You get a source inventory, a short list of the decisions that matter, and a scoped plan.
  2. Architecture. The data model and measures are designed before any page is drawn.
  3. Design. The report is built around its audience and the screen it is usually read on, with a review round with your team before anything is final.
  4. Handoff. Written documentation of the model, measures and refresh setup, and a walkthrough with whoever will own the report. The files are yours, with no ongoing dependency on the studio.

Who it suits

Teams whose reports work but are slow, look inconsistent from page to page, or are rebuilt by hand from exports every week. Teams where two people get two different numbers for the same metric because the logic lives in several places.
